# 交付前检查与交付

## 九、交付前检查
- [ ] 每份材料的每个主题都对应到了知识点（列出覆盖对照表）
- [ ] 图里没有循环；所有前置 ID 都存在；学习顺序里没有用到还没学过的知识点（后补前置有回看卡片）
- [ ] 打开网页确认地图板块里能看到拓扑图，点一个知识点能亮出它的前置和后续（只有内容极窄或没有先后关系时可以不画，并在地图位置写明原因）
- [ ] 自学类：关键事实和公式核实过；转写错误已更正；补充内容已标注；从零规划时，推荐的资源都是实际查到的，链接可用，章节或讲次对得上
- [ ] 备考：每道考题都映射到了知识点；闭包完整；深度校准有依据；缺口已列出；扎实版每种题型有 3 道以上仿真题，真题已封存
- [ ] 每个知识点都有掌握标准，并且至少有一道对应深度的题
- [ ] 每一课最后都有逻辑主线，并且每一环都链接到对应的步骤；地图里有模块之间的主线；每一步的卡片顶部都显示主线位置
- [ ] 计算题和代码题的答案用代码验算过；每个预设的错误答案确实会触发对应的提示
- [ ] 全站扫描：公式里没有未转换的 `<` `>`；所有 (I)–(VI) 序号都是统一样式（包括选项和知识点标题）；表格标签列不换行
- [ ] 上手成本：每个板块有一行使用说明；全站只有一种题卡；题目只有“已掌握”一个状态开关；每一步都按“一步讲解的固定写法”的顺序
- [ ] 可撤销：逐一试过每个会留存的操作（勾选、作答、计时清零、Cheat Sheet 移除、导入进度码、一键重置），都能恢复到操作之前
- [ ] 打开网页实际看一遍：手机宽度和深色模式下没有错位；标签切换、hash 跳转、公式、拓扑图、课件链接、判分、计时都能用；更新后旧进度还在
- [ ] 校验脚本 `scripts/validate_course.py` 没有报错
- [ ] `course.json` 已保存到两个地方

## 十、交付
- 新建或切换到备考时：用户能判断拓扑图对不对时（有课件、考试范围或相关基础），先发知识点拓扑图（可以是只含地图的第一版网页）给用户确认，再生成完整网页；用户是入门者或时间来不及确认时直接生成，但拓扑图照样要有。从零规划时，先发学习路线给用户确认。轻量入门不需要确认，直接生成网页，并用一句话说明预计学习时长。
- 增量更新时：直接更新，然后一句话说明新增和更正了几个知识点，并列出待确认的矛盾。
- 每次附一句话：说明这次用的是哪种类型；可以把进度码发过来，下次会针对薄弱点加强。
- 用户提出修改意见后：先改网页，再按“八之二、自我改进”判断问题范围，需要时在回复最后提出 skill 迭代建议，确认后才改 skill。
