# 无痛学习网页（Codex 版）

把学习材料做成**一门课一个网页**：先讲清前置，再讲后续；知识点是一小撮一小撮能讲通的内容，彼此之间有拓扑关系；每一步都能用题检验是否掌握。一门课是长期项目，可以每周加入新材料，备考时在同一个网页里加上考试相关的部分。

这个文件只写**必须做到的事**和**整体流程**。各环节的细则放在 `references/` 里，做到哪一步就读哪个文件，读完照做。

---

## 一、必须做到（每次都要逐条满足）

1. **学习目的只听用户说**。学习还是备考、备考是冲刺还是扎实，必须由用户亲口说出。材料里写着考试日期或考试要求，只能当参考信息，不能据此替用户决定。用户没说时，先提问，并停下来等回答（提问方式见第二节）。
2. **知识点是“一小撮能一口气讲通的内容”**。通常围绕一个小问题（为什么需要 → 怎么做 → 得到什么），包含 2–5 个紧密相关的定义、性质或方法，学完能用一组题检验。更细的内容放在知识点内部按“一步讲解”展开，不单独成为节点。“Module 7：Binomial regression、link、MLE、Wald 区间”把整个模块当成一个节点，太粗，**不合格**；把每个定义都拆成节点，拓扑图就成了课件目录，太碎，**也不合格**。拆分细则见 `references/new-course.md` 第 3 步。
3. **拓扑图必须生成，而且是知识点拓扑图**。前置关系可以跨模块连线（例如 Cook's distance 要接到帽子矩阵，Wald 检验要接到 Fisher information）。一条从 1 排到 11 的模块直线、按模块缩进的大纲，都**不是**拓扑图。只有两种情况可以不画：内容极窄（只有 1–3 个知识点），或者知识点之间确实没有先后关系。这时要在地图的位置写明原因。
4. **确认稿用网页给，之后一直在同一个网页上改**。第一版网页只含地图（以及备考时的考情），让用户直接在可点击的图上确认；确认后，在同一个网页上分批补课堂和题库。交付方式见第三节。
5. **只在用户能判断时才请他确认拓扑图**。用户有课件、知道考试范围，或者有相关基础时，才请他确认。用户是入门者时不请他确认，因为他判断不了对错；你自己对照课件或权威来源核对一遍，再直接放进网页。不管确不确认，拓扑图都照样生成。
6. **备考时，考题拆到小问**。每一小问列出做对它必须会的知识点，再沿前置往回找出全部需要的知识点（考试闭包），并按题目的问法定每个知识点要学到多深。细则见 `references/exam-mode.md`。
7. **每一步按固定顺序写**：为什么现在学 → 直觉 → 定义或公式 → 人话 → 例题 → 常见卡点 → 自测 → 考题出处。每课最后一步是逻辑主线。细则见 `references/teaching.md`。
8. **全站只有一种题卡**。“已掌握”只由用户自己勾；答错时给针对性的解释。细则见 `references/mastery.md`。
9. **`course.json` 是数据正本**。知识点用稳定 ID，更新后用户的进度不会丢。结构见 `references/data-model.md`。
10. **交付前实际检查**：运行 `python3 scripts/validate_course.py <路径>/data/course.json`，修到没有错误为止；打开网页确认拓扑图能显示，点一个知识点能亮出它的前置和后续。完整清单见 `references/checklist.md`。

### 确认稿最低要求
- 知识点粒度按第一节第 2 条。数量只用来自查，不是指标：完整课程大约 40–80 个，几个模块的备考大约 20–40 个；明显偏离时，回头检查是拆粗了还是拆碎了。不要为了凑数硬拆或硬合。
- 每条写明：编号、所属模块、一句话内容、前置编号（可以跨模块）、对应的考题小问（备考时）。
- 写明知识点总数；备考时还要写考试闭包里有多少个知识点。
- 以可点击的拓扑图网页呈现：点一个知识点，亮出它的全部前置和后续；备考时提供“按考题看”，亮出做某一小问需要的全部知识点。
- 模块图可以作为总览放在旁边，但不能代替知识点拓扑图。

### 知识点清单样例（格式参考）
| 编号 | 模块 | 内容 | 前置 | 考题小问 |
|---|---|---|---|---|
| 3 | M0 线代 | 谱分解：\(A=\Gamma\Lambda\Gamma^\top\) 的含义，用它求 \(A^{-1}\)、\(A^{1/2}\)，判断正定 | 1, 2 | — |
| 6 | M1 协方差 | 样本均值与样本协方差矩阵 \(S\)：定义、矩阵写法、无偏性 | 5 | 模拟卷 Q1(a) |
| 15 | M4 PCA | 第一主成分：为什么最大化 \(\operatorname{Var}(a^\top X)\)、为什么加约束 \(\lVert a\rVert=1\)、用拉格朗日乘子推出它是 \(\Sigma\) 最大特征值对应的特征向量 | 14, 3 | 模拟卷 Q2(a)(b) |
| 16 | M4 PCA | 后续主成分与方差解释比例：正交约束、碎石图、选几个主成分 | 15 | 模拟卷 Q2(c) |

15 号的前置 3 号在线代模块里，这就是跨模块连线。15 号内部再按“一步讲解”分成目标、约束、推导、结论几步来讲。

## 二、怎么向用户提问

- 有 `request_user_input` 工具时，就用它：一次 1–3 个问题，每题 2–4 个选项，推荐项放在第一个。
- 没有这个工具时（Codex 默认只在 Plan 模式下提供），在回复里写出编号选项，例如“A. 扎实版 B. 冲刺版”，然后**结束这一轮回复，等用户回答**，不要边问边接着做。
- 用户可以在 `~/.codex/config.toml` 里打开普通模式下的提问工具：
  ```toml
  [features]
  default_mode_request_user_input = true
  ```
  遇到需要提问、但工具不可用的情况时，可以顺带提醒用户一句。
- 什么时候必须问：
  - 学习目的没说
  - 备考没说冲刺还是扎实
  - 材料里的信息互相矛盾，例如公告里的考试范围前后不一致
- 什么时候不问：轻量入门（只想弄懂一个概念、总时长少于 3 小时），以及能从材料里确定的事实。

## 三、网页交付

- **能用 Sites 插件时**（用户提到 Sites，或者你的工具里有 Sites）：确认稿网页用 Sites 发布，把链接给用户；之后的所有修改，包括补课堂、补题库、增量更新，都在**同一个 site** 上更新，不另建新的。Sites 发布的是正式地址，新建的 site 默认只有自己能看，分享前先提醒用户检查分享范围。
- **不能用 Sites 时**：写到课程文件夹的 `_学习网页/index.html`（单文件、数据内嵌、浏览器直接打开），把路径告诉用户；之后的修改都改这同一个文件。
- 两种方式下，`data/course.json` 都保存在课程文件夹的 `_学习网页/` 里，作为数据正本。
- 网页里不能调用 AI：Cheat Sheet 等需要整理的内容先存在 localStorage，再提供“复制全部（给 AI 用）”按钮，由用户发回给你整理。
- 课件链接：本地网页用相对路径指向 PDF 并带 `#page=N`；托管网页把引用到的课件页导出成图片，随网页一起发布。

## 四、流程

| 情况 | 做法 | 要读的文件 |
|---|---|---|
| 先定规格 | 判断是轻量入门、自学、从零规划、课程学习、备考·冲刺还是备考·扎实；目的不明就提问 | `references/profiles.md` |
| 新建（有材料） | 读完全部材料 → 拆知识点 → 建知识点拓扑图 → 网页确认稿 → 用户确认后分批生成课堂和题库 | `references/new-course.md`、`references/page-spec.md`、`references/teaching.md`、`references/mastery.md` |
| 没有材料 / 轻量入门 | 从零规划：先调研、出学习路线；轻量入门：直接生成精简网页（仍然要有小拓扑图） | `references/new-course.md` |
| 备考 | 考题拆到小问 → 反推闭包 → 深度校准 → 考情板块 | `references/exam-mode.md` |
| 每周加入新材料 | 合并知识点，处理冲突，在同一个网页上更新 | `references/incremental-update.md` |
| 用户不满意 | 先改网页，再判断要不要改 skill | `references/self-improve.md` |
| 交付前 | 逐条检查 | `references/checklist.md` |

其他细则：
- 读材料时每个文件都读完；扫描页和手写页要做 OCR，做不到时告诉用户哪些页没读到。
- 能联网时，用来做从零规划和事实核实。
- 规则的修改记录见 `references/rule-changelog.md`。
