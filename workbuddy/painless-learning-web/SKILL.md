# 无痛学习网页

把学习材料做成**一门课一个网页**，让用户按顺序学下去就能懂、学得对，并且能用题验证自己真的掌握了。一门课是一个长期项目：可以每周加入新材料；备考时在同一个网页里打开考试相关的部分。用户手上没有材料时，先帮他规划学习路线、找权威资源，再做网页。

## 零、环境约定（适配不同的 AI agent）
这个 skill 原本为 Claude 写成，下面说明在 Codex、WorkBuddy 等其他 agent 里怎么落地。正文里的规则都照做，遇到环境能力不同的地方按这里处理。
- **读文件**：用你能用的文件工具或脚本读取用户给的文件夹（PDF、PPT、DOCX、图片）。不能做 OCR 时，告诉用户哪些页没读到。
- **联网**：有搜索工具时用于从零规划和事实核实；没有时说明，并请用户提供材料。
- **提问**：需要问用户时一次问完；有选项式提问工具就用。
- **网页放在哪**：默认写到课程文件夹里的 `_学习网页_<主题>_<日期>/`（没有课程文件夹时，在当前工作目录建同名目录）：`index.html` 是整个网页（数据内嵌，浏览器直接打开）；`data/course.json` 是数据正本；`img/` 放来源截图。
- **交付只有一个渠道：发布成可访问的链接（发布版），不走资料库单页**。本地生成、校验、自己打开看过之后，直接发布（`workbuddy_sites_deploy`，多文件静态站点），回复里给分享链接。不要停在上传前问“要不要发布”——用户要的是点开就能看的网页，不是本地文件。只有在当前环境完全没有发布能力时，才退回只给本地文件，并明确说一句“这次没能发布”。
  - **为什么不用资料库单页**：资料库页面是单文件产物，装不下 `img/` 目录。硬把几十张图 base64 塞进去，页面会涨到十几 MB，实际结果是干脆不做截图——2026-11-14 那版就是这么丢掉全部课件截图的。发布版是多文件站点，图片走相对路径 `img/xxx.png`，天然支持。
  - **必须记住发布版在哪**：第一次发布后把 `deploy` 写进 `data/course.json`：`{"channel":"sites","dir":"_学习网页_<主题>_<日期>/","app_name":"<课程代码> <主题>","share_link":"https://…","app_id":"wbapp_…","published_at":"<日期>"}`。之后每次改都先读这个字段，找到目录再改；改完重新发布到同一个 app，链接保持不变。**不知道文件在哪就先找**（看 `course.json` 的 `deploy.dir`、看目录名、看 `.wbapp_*.genie`），不要新建一份——那会让用户手上出现两个版本。
  - 改的方式两种都行：直接改发布目录里的 `index.html` + `data/course.json`，或者改本地正本再整目录重新发布。优先改正本再重新发布，因为发布目录可能被覆盖。
  - 本地文件夹始终保留，它是可以重新生成网页的正本；发布版是给用户看的成品。
  - 发布版是**联网**产物：用户从链接打开，断网就打不开。所以“离线可读”不是发布版要解决的问题；只有在用户明确要求“下载到本地、考前没网也能看”时，才需要把 MathJax 内联进 HTML（见三·公式）。
- **网页里默认不调用 AI，但技术上可以调**：纯静态页面不能安全地存放 API 密钥——写在前端 JS 里等于公开，任何人 F12 就能拿走并盗用配额。所以默认做法是把内容存在浏览器里、导出给用户、由用户在对话里交给 AI 整理。确实需要网页自己调模型时（例如粘贴即识别），必须有一个保管密钥的后端或云服务来转发，并在交付时把这个依赖和代价说清楚。
- **计时只做“整卷 / 本步”两级，不做每题计时**：用户明确表示不需要知道“这道题卡了多久”，做题时的分秒计时只增加压力、不产生决策。整卷计时（模拟考试）和每一步的用时（知道这一步大概花多久）够用。
- **验证**：能运行 Python 时，运行 `python3 scripts/validate_course.py <路径>/data/course.json`，修到没有错误为止；能用浏览器或无头浏览器时，打开 index.html 检查渲染和交互；做不了的检查要告诉用户。

### 零之二、硬性交付清单（缺一项就是没做完，不是“下次注意”）

下面 14 项是最容易在长文档里被漏掉的。交付前逐条打勾，缺一项就不算做完。做法见括号里的章节。

| # | 项 | 一句话验收 | 详见 |
|---|---|---|---|
| 1 | 拓扑图 | 分层布局、节点是手写短名、能拖动、点节点弹详情面板、模块可点筛选 | 三·拓扑图 |
| 2 | 详情面板两个方向 | 既列「直接前置」，也列「课堂里一起讲」和「学会之后能接着学」 | 三·拓扑图 |
| 3 | 符号翻译器 | 数理类课程必须有，和术语弹窗并列：符号 / 形状 / 随机还是固定 / 大白话 / 例题里的值 | 三·通用功能 |
| 4 | 来源截图 | 知识点引用到的课件页全部导出成 `img/`，点出处弹窗看原页 | 三·来源截图 |
| 5 | 学习路径按天分段 | 每段写日期、时长、要学的编号、检验题、当天已掌握 x/y、「开始第 N 天」入口 | 六.1 第 7 条 |
| 6 | 前置知识的位置 | 材料里有的前置按原位置出现；材料里没有的放在第一次用到之前补讲；拓扑图上都能点到 | 四.5 |
| 7 | 考情逐题表 | 按题号一眼看清：分值、考点、可点的知识点必有；公式、闭包等按需加；一屏放得下 | 六.1 |
| 8 | 真题手册 | 原题 + 中文翻译 + 分值 + 出处 + 思路 + 折叠答案；整卷计时 + 阅读时间 + 每题建议用时 | 六.4 |
| 9 | 掌握度按分值 | 备考页「已掌握」显示成 `0/100 分`，不是 `0/113 题` | 八.4 |
| 10 | 计时两级 | 整卷计时 + 每一步用时；**不做每题计时** | 三·计时器 |
| 11 | 公式真的排出来 | 不是源码、不是文字拼的、不是图片；**罗马字/上下标/帽子不能丢**；体检四数（正文残留 `$…$` / SVG 里的 `$` 或 `\` / 空 `mjx-container` / 控制台错误）全为 0。发布版把 MathJax 放 `vendor/` 本地引用，不走 CDN、也不内联进 HTML | 七·公式 |
| 12 | 已发布 + 记住位置 | 回复里是可分享链接；`data/course.json` 里有 `deploy`（目录 / 链接 / app_id） | 零·环境约定 |
| 13 | 视觉 | 参考 `references/ui-kit.css` 的呈现形式（**不是照抄模板**，布局骨架按本课需要选）；**本课有自己的主题色并写进 `theme`**，和其它课不撞色；手机 390px 单独调过 | 七·视觉 |
| 14 | Cheat Sheet（有暂存功能时） | 粘贴文字/图片、IndexedDB 存 Blob、缩略图倒序、点开放大翻页、删除可撤销、**导出/导入备份**；不接 AI、不自动打标签、不排序 | 六.5 |

**为什么要有这张表**：上面每一条本文件里都写了，但散在十几节、全文六百多行，实际执行时会被漏掉（2026-11-14 那版就漏了 3、4、5、9 四项，用户对照另一版才发现）。散落的规则等于没有规则，所以集中成一张表。新增规则时如果属于“交付物”，同时加到这张表和第九节。

## 一、先定规格

先从用户的话和材料判断属于哪一类。判断不了时，用一次提问问清（最多 3 个问题）。用户不在场时，选最合理的一类，并在交付时说明选了哪一类、为什么。

**学习目的只听用户说**：学习还是备考、备考是冲刺还是扎实，必须由用户亲口说出。材料里写着考试日期或考试要求，只能当参考，不能据此替用户决定。用户在场但没说时，先提问（用选项），并停下来等回答，不要边问边接着做。轻量入门不用问。

| 类型 | 典型情况 | 目标 | 重点 |
|---|---|---|---|
| **自学理解** | 只有教材、网课转写稿、文章；不为考试 | 理解，并且学对 | 讲清讲对；用理解题验证；不做考情分析；计时器默认收起 |
| **轻量入门** | 只是不了解某个概念或小主题，想快速入门；预计总学习时间少于 3 小时 | 快速建立正确的理解 | 不出路线、不等确认，自己定路线后直接生成网页（见“四之三”） |
| **自学·从零规划** | 只知道想学哪一块，手上没有材料 | 由浅入深地学会 | 先调研、规划路线、找权威课程和教材，用户确认路线后再做网页；讲法要循循善诱（见“四之二”） |
| **课程学习** | 学期中，每周或每两周给课件和 lecture 转写 | 跟上课程，学懂每周内容 | 增量更新；按周推进；跟课程范围严格对齐 |
| **备考·冲刺** | 离考试近，时间少 | 短时间拿下高频分 | 考情校准；只学核心和重要；直接用真题检验 |
| **备考·扎实** | 要冲高分，时间够 | 真正掌握 | 考情校准；闭包内全部知识点讲透；先刷仿真题，真题封存到最后 |

需要了解的情况（能从材料推断的就不问）：
- 学习目的：理解、跟课，还是备考；备考的话，是冲刺还是扎实（这一条不能从材料推断，用户没说就问）
- 有什么材料
- 现在的基础
- 截止日期或考试日期
- 每天能学多久
- 考试形式：用什么语言作答、能不能带笔记、计算器限制

同一门课可以先是“课程学习”，期末再加上“备考”。这时不新建网页，在原来的网页上打开备考部分（见第三节）。

## 二、课程数据文件

每门课维护一个 `course.json`，网页由它生成。更新时改这个文件，再重新生成网页。

保存在两个地方，保证下次对话能接着做：
1. 网页文件夹里的 `data/course.json`
2. 用户的课程文件夹 `_学习网页/course.json`（能写入时）

更新前先读这个文件。两处都找不到时，从已发布的网页里还原，并告诉用户。

```json
{
  "course": {"code":"…", "name":"…", "profile":"self|self-plan|course|exam-sprint|exam-deep",
             "exam": {"date":"…", "format":"…", "answer_lang":"en|zh", "allowed":"…"}},
  "sources": [{"id":"W03L1", "file":"…", "url":"…", "type":"lecture|transcript|textbook|tutorial|lab|assignment|sample_exam|past_exam|exam_info|web", "week":3, "added":"…"}],
  "modules": [{"id":"M-sql-basic", "name":"…", "order":5}],
  "points": [{
    "id":"sql-left-join",        // 稳定 ID，生成后永不修改
    "no":57,                      // 显示编号，每次生成时重新排
    "title":"一句话内容",          // 完整说法，可以带公式
    "short":"左连接",             // 节点上用的 4–10 字短名，手工写，不截断
    "module":"M-sql-basic",
    "week":5,
    "tier":3,                     // 3 核心 / 2 重要 / 1 次要 / 0 不考（自学类可以不分级）
    "depth":"apply",              // recall 认得 / explain 会解释 / apply 会用 / transfer 能迁移
    "pre":[{"id":"sql-inner-join","kind":"hard"}, {"id":"null","kind":"soft","why":"IS NULL"}],
    "cluster":"k-join",           // 可选：同一步课堂里一起讲的点，归到同一个簇
    "cluster_with":["内连接","外连接","笛卡尔积"],   // 详情面板「课堂里一起讲」
    "src":[{"source":"W05L1","page":24,"img":"img/W05L1-p24.png"}, {"source":"W05L1-transcript","time":"32:10"}],
    "exam_refs":["样卷2 Q2A"],
    "in_exam":true,               // 是否在考试闭包内（备考）
    "day":3,                      // 落在学习路径第几天（备考冲刺）
    "minutes":7,                  // 学这一点预计几分钟，用于算当天时长
    "mastery":"做对什么题算掌握（一句话，必须能用题检验）",
    "status":"active|merged|deprecated",
    "changed":"日期：改了什么",
    "note":"不考 / 补充 / 老师说过…"
  }],
  "storyline": [{"from":"M-tree", "to":"M-rf", "why":"一句话：前一个模块留下了什么问题，后一个模块怎么接上"}],
  "lessons": [{"id":"L-w05", "track":"learn|review", "title":"…", "points":[…], "steps":[…],
               "storyline":[{"role":"问题|思路|做法|结果|新问题", "text":"一两句", "formula":"可选，写最简形式", "steps":[3,4]}]}],
  "questions": [ … 见第八节 … ],
  "changelog": [{"date":"…", "summary":"…", "added":[…], "changed":[…], "conflicts":[…]}],
  "course_notes": [{"date":"…", "note":"只适用于这门课的偏好或修正（例如记号、某个模块要讲更深），以后更新这门课时一律遵守"}]
}
```

规则：
- **ID 稳定**：进度、勾选、错题都按 ID 存，所以更新后用户的进度不会丢。
- 不删知识点。不再需要的标 `deprecated`；合并的标 `merged`，并指向新 ID。
- `pre` 只写直接前置。`hard` 表示必须先学；`soft` 表示只用到其中一个概念，并写明是哪个。

## 三、网页结构：一门课一个网页

整门课是**一个网页**（`_学习网页/index.html`，见“零、环境约定”）。用顶部标签切换板块，用 URL hash 定位（例如 `#map`、`#lesson/L-w05/3`、`#q/q-id`），方便板块之间互相跳转。

### 板块，以及每种类型显示哪些

| 板块 | 内容 | 自学（含从零规划） | 课程学习 | 备考 |
|---|---|---|---|---|
| **地图** | 模块拓扑图、全部知识点（勾选框、前置、来源）、进度、“本次更新”面板 | ✓（从零规划时就是学习路线，附推荐资源） | ✓ | ✓，加“考试视角” |
| **课堂** | 一步一步地讲，每步带自测 | ✓（按章节或阶段） | ✓（按周） | ✓，加“复习线” |
| **练习** | 按知识点出的自编题（备考时仿真题也放这里，用标签区分）；“未掌握”筛选就是错题本 | ✓ | ✓ | ✓ |
| **考情** | 考试事实、材料优先级、逐题表、模块分量、不考清单、老师说过的话 | — | — | ✓ |
| **仿真题** | 并入练习页，用“仿真”标签筛选，不单开板块 | — | — | 扎实版 |
| **真题** | 样卷和往年卷（刷题手册） | — | — | ✓（扎实版先封存） |
| **Cheat Sheet 暂存** | 学习中随手存下不想背的内容，之后由 AI 结合上下文整理，最后据此生成笔记纸（见第六节第 5 条） | — | — | ✓（考试允许带笔记时） |

### 拓扑图必须生成
- 每个网页的地图板块里都要有知识点拓扑图。无论哪种规格、时间多紧、是否跳过了确认，都必须生成。前置知识也要画进去（例如学“API 是什么”，要把客户端、服务器、HTTP 请求这些前置画出来）。
- 只有两种情况可以不画：要学的内容极窄（只有 1–3 个知识点），或者知识点之间确实没有先后关系。这时在地图的位置写一句为什么没有拓扑图。
- 时间紧时可以减少课堂步骤和题量，但不能删拓扑图。

### 导航布局（课堂和刷题优先）
- 课堂和刷题是主体，地图、考情、学习路径只是总览，不能占据顶部的大部分空间。
- 顶部压成一行粘性栏：课程代码 + 主板块标签 + 倒计时 / 进度 / 术语 / 进度码小按钮。主板块只有：**课堂**（默认打开）、**刷题**（子页：练习、真题）、**总览**（子页：地图、考情、学习路径）、**Cheat Sheet**（有暂存功能时）。
- 第二行是当前主板块的子页标签，以及单行的 Cheat Sheet 输入框（聚焦时才展开）。
- 考情板块在所有备考网页里保留，内容写完就不再变；学习路径会随进度变化，用户不一定参考，放在总览里即可。

### 上手成本要低
拿到网页的人不该需要先学怎么用它。
- 每个板块第一次打开时，顶部一行浅色说明（可以关掉），一句话说清这一页怎么用，例如“没把握的题不要勾‘已掌握’；筛选‘未掌握’就是你的错题本”。
- 全站只有**一种题卡**：题面 → 选项或输入框 → 提示 / 看答案 → 右上角“已掌握”勾选框。课堂自测、练习、真题都用它，学会一次到处通用。
- 按钮写动词文字（“看答案”“下一步”），不用只有图标的按钮；一页里的筛选和开关尽量少，不常用的功能不做。
- 同一件事只给一个入口、一种状态，不要让“已订正”“撤销”“已掌握”这类意思相近的状态并存。

### 所有留存的操作都能撤销
拿到新网页的人会先到处点点试试。所以凡是会被保存下来的操作，都要能恢复到操作之前，试错不留痕迹。
- **开关类**（“已掌握”、知识点勾选、步骤“已完成”）：再点一次就取消，不要做成只能打勾、不能取消。
- **作答记录**：每道题有“重做”按钮，清掉这道题的作答和反馈，回到没做过的样子。
- **清零、移除、导入这类会丢东西的操作**：做完后底部弹出提示条“已清零 · 撤销”，约 8 秒内点“撤销”就完整恢复。不用浏览器的 confirm()。
  - 计时器清零、Cheat Sheet 移除条目、导入进度码都走这个提示条
  - Cheat Sheet 的移除用软删除：移到页面底部的“最近移除”里，过了提示条的时间也能从那里恢复
  - 导入进度码前自动备份当前进度
- **一键重置**：进度码弹窗里放“清空我的全部记录”，方便试玩完从头开始。点之前先自动备份，清空后同一个弹窗里保留“恢复刚才的记录”按钮。
- 实现上：每次会丢东西的写入前，把受影响的那部分状态存一份快照；撤销就是写回快照。一键重置的备份存在单独的 localStorage 键里，直到下一次重置才覆盖。

### 学习模式和考试模式共存时怎么放
- **地图只有一张**，提供“学习视角 / 考试视角”切换：
  - 学习视角：按周或按章节排，显示全部知识点
  - 考试视角：按考试分量排；考试闭包以外的知识点变灰；显示考试出处标签和学习路径

  两种视角共用一套勾选进度。
- **课堂分两条线**：
  - 学习线：学期中按周做的课，一直保留
  - 复习线：备考时新增的课，按学习路径排。复习线不重复讲已经学过的内容：已学过的知识点只给一张压缩回顾卡片，链接到学习线的原讲解，再补上考试角度（题目怎么问、答到多深、常见失分点）。只有考试要用、学习线没讲透的地方才展开讲
- **练习题库只有一个**：平时的自测题和备考的仿真题都放在里面，按标签筛选。错题本跨模式共用
- **考情、真题**这两个板块只在备考时出现。真题手册属于备考，不放进学习模式

### 网页里的通用功能
- 顶部：课程名、类型、总进度，以及考试倒计时（备考时）
- 计时器（所有规格都有，包括轻量入门）：
  - 位置：每一步卡片的右上角，不要只藏在侧栏里。内容是“本步用时 mm:ss · 本课累计”，每秒刷新；有“暂停 / 继续”“清零”“收起”按钮（清零只清当前一步，清完弹出“撤销”提示条）；暂停状态跨步骤保持；用时记在当前的步骤或题目上。
  - 默认显示方式按规格定：课程学习、备考·冲刺、备考·扎实默认展开，能看到秒数在跳；自学理解、自学·从零规划、轻量入门默认收起，只在右上角显示一个圆形或椭圆形的小时钟按钮，不显示数字，点一下才展开看用时。用户展开或收起后记住他的选择。
  - 离开检测：鼠标、键盘、滚动、触摸都没有动静满 3 分钟算“离开”，切走标签页也算。离开期间照常计时，用户一回来（任何操作或切回标签页）就在右下角弹出小窗（宽约 260px，不遮挡课件，不用 confirm()）：“你离开了约 N 分钟。这段时间算作学习吗？[算学习] [不算]”。选“不算”就从当前步骤的用时里扣掉这段时间；暂停时不检测离开。

  - **展开状态必须做成一眼看得见的胶囊，不能做成一串灰色小字**（收起状态就是右上角的小圆钟按钮）。踩过的坑：把计时器写成 `font-size:11.5px; color:var(--ink2)` 的纯文本，宽度不够时还会折到卡片第二行，看起来就像一行斜体注释——用户会直接问“你为什么没给我加计时器”。正确做法：整块用一个胶囊承载（浅蓝底 + 细边框 + 圆角 99px + `⏱` 图标 + 等宽数字 `font-variant-numeric:tabular-nums`），字号 ≥ 12.5px，`flex-basis:100%` 独占一行右对齐，暂停时整块换成暖色（橙），状态一眼可辨
  - **计时只做两级，不做每题计时**：① 每一步卡片上的“本步用时 mm:ss · 本课累计”（知道这一步大概花多久）；② 真题手册的整卷计时（模拟考试）。**不要**给刷题页每道题加计时——用户明确说过不需要知道“这道题卡了多久”，做题时的分秒计时只增加压力、不产生决策。
  - 顶栏的“今日累计”属于可选增强，不是硬性要求；要做就做成一个胶囊，不做也完全可以。
  - 验收：截图里不用找就能看见计时器；暂停后数字停住；清零能撤销
- 主线弹窗：随时可以打开当前这一课的逻辑主线，并高亮“你在这里”（见第七节“逻辑主线”）
- 术语对照弹窗（中英对照，每个附一句话解释）；数学、统计类课程再加一个符号翻译器
  - 符号翻译器的五列：符号 / 形状（n×1、数、矩阵）/ 随机还是固定 / 大白话一句 / 在贯穿例子里的值。按主题分组，组标题单独一行（不用编造符号）。
  - **顺手定义一套 LaTeX 宏**，把全书反复出现的记号缩短：`\y \X \bb \beps \rk \MVN \Xt \bgh` 之类，在页面里 `\newcommand` 一次。好处有三：数据文件里公式短一半、不容易写错、MathJax 渲染更稳。宏名用两三个字母，别和 MathJax 内置的撞（`\vec`、`\det`、`\lim` 这类不要重定义）。
  - 符号表不是只给学生看的装饰：写讲解时逐条对照它，凡是表里有的符号，正文第一次出现必须已在表里。
- 课件链接：用相对路径指向课程文件夹里的原 PDF，并带 `#page=N`（浏览器自带的 PDF 阅读器会跳到对应页）；转写稿标注时间点；网络资源给出原始链接
- 进度码：导出一段文字发给 AI，AI 据此知道哪里薄弱。导入时只增加勾选，不删除；导入前自动备份，可以撤销
- 所有状态按“课程代码 + 稳定 ID”存在 localStorage，读写一律包 try/catch
- 一套统一的配色，带深色模式，同一门课前后保持一致
- 适配手机：侧栏改为堆叠在顶部，表格可以横向滚动，并适配安全区
- 公式用 MathJax 的 SVG 输出。**按交付形态决定怎么引**：
  - **发布版（默认，用户从链接打开）可以直接用 CDN**：`https://cdnjs.cloudflare.com/ajax/libs/mathjax/3.2.2/es5/tex-svg.js`。页面本身就是联网产物，断网时整页都打不开，内联 MathJax 换不来任何东西，只会让文件从 475 KB 涨到 2.6 MB、首屏变慢。**不要用不带 `-full` 的 `tex-svg.js` 之外的自定义组合**：它在运行时会去 CDN 取没静态打包的扩展，个别网络下会整条公式失败，换 `tex-svg-full.js` 就没事。
  - **只有用户明确要求“下载到本地、考前没网也能看”时，才把 MathJax 内联进 index.html**（约 2.1 MB，单文件涨到 2.5 MB 左右可接受）。
  - 内联时也必须写 `startup: {typeset: false}`，排版改由页面自己调度：把待排版节点收进队列 → 去抖 50 ms → 串行 `typesetPromise` → 每轮前调一次 `MathJax.typesetClear()`。否则整块重渲染后，MathJax 内部残留的公式项会让 `updateDocument` 去 replaceChild 一个已脱离文档的节点，抛 `Cannot read properties of null (reading 'replaceChild')`，公式同样不显示。
  - 验收方法（两种形态都要做一次）：无头浏览器截图，确认公式是排版后的图形，而不是 `$...$`、`\mathbf` 这类源码。判断“是不是 CDN 挂了”用 `--host-resolver-rules="MAP * 127.0.0.1"` 把外部域名指到本地再截一次，和正常截图对比。
- 拓扑图（硬性要求）：
  - 用分层的有向图布局：前置在上（或在左），后续在下（或在右）。用 Graphviz dot（或 dagre 等同类布局库）预先算好坐标，在页面里画可点击、可缩放的 SVG。**不要**按模块分列、每列从上往下堆，那样连线会交叉成一团。模块用节点颜色或分组框区分。
  - 节点上只放纯文字短标题（中文，约 15 字以内），**不放 LaTeX**：SVG 里的文字不经过 MathJax 渲染，会露出 `\mathbf` 这样的源码。完整标题和公式放进点开节点后的侧栏。标题太长时按词断行，不从中间截断。
  - **默认 fit 全图**（一屏看到整体形状和主线走向），不要一进来就放大到只看得见局部——用户第一眼要的是“这门课长什么样、有几条主线”。全图下节点文字必然很小，靠下面四条补：① 短名压到 4–6 字；② 悬停出原生 `<title>` 全称；③ 滚轮 / `＋−` / 双击节点放大到可读；④ **右侧常驻面板**显示选中节点的完整信息，所以不依赖在图上读字。另给一个「看全图」按钮回到初始视图。
  - 右侧面板要常驻（不是浮层），宽度 300–340 px，选中前显示一段「从哪里开始」的引导（总点数、闭包内多少、建议从哪一天/哪道题入手），选中后换成详情。这样图在左、信息在右，用户不用来回关面板。
  - **图必须能拖动平移，不能只做缩放**：按住空白处或节点都能拖，拖动方向与画面移动方向一致（拖右→内容右移）；拖动结束后补发的那个 click 要吃掉，否则一松手就顺手点亮一个节点。缩放以光标为锚点，并给上下限（默认视图的 1/8 到 3 倍），否则会缩成针尖或糊成一团。
  - **手机上没有滚轮**，所以缩放一定要有 `＋ / −` 按钮（以视图中心为锚点）；同时把 `touch-action` 设成 `pan-y`，让横向拖动能平移图、竖向滑动仍能滚动页面，不要把整块图变成滚不动的死区。
  - 踩过的坑：只写了 `pointerdown/pointermove` 累加位移，但重绘时只按 `base` 重设 viewBox、没有把位移算进去，结果拖拽完全没反应（用户会说“拖不动，只能滚轮缩放”）。位移必须换算成 viewBox 单位写回 `base.x/base.y`：`b.x -= dpx * b.w / rect.width`。
  - 点一个知识点，亮出它的全部前置和后续；“按考题看”亮出做某一小问需要的全部知识点。
  - **节点上写「概括性短名」，不写完整标题**：知识点标题是给人读的完整说法（往往带公式、带条件，二三十字），直接放到节点上必然被截断，用户看到的永远是前半句。每个知识点单独维护一个 4–10 字的短名（`short` 字段），只回答“这一点在讲什么”，例如「满秩下的最小二乘：β̂=(XᵀX)⁻¹Xᵀy」→「最小二乘估计」。短名要手工写，不要用截断或首句截取糊弄。
  - 节点可以带**学习顺序编号**（`no`），用不带 `#` 的纯数字小字放在短名前面，并在图上方的说明里写明“编号就是推荐的学习顺序，每个前置刚好排在第一次用到它之前”。不要用 `#47` 这种写法（像代码里的引用号，不好看），编号要小、浅灰，不抢短名。完整标题和公式留在右侧面板。
  - **点节点必须弹出详情面板，不能只在角落显示一行字**：面板里按这个顺序放——① 编号 + 完整标题（带公式，走 MathJax）；② 一行标签：所属模块 / 重要度 / 深度 / 第几天 · 约几分钟；③ **课堂里一起讲**（同一步讲的其他点，可点）；④ 掌握标准；⑤ 状态（未学 / 已学；相关题已勾“已掌握” x/y）；⑥ 考过的题（可点，跳到题）；⑦ 来源（课件名 + 页码，可点弹窗看原页截图）；⑧ **直接前置**（可点）；⑨ **学到这里，要先会的全部 N 个（还差 M 个）**——沿 hard 前置递归展开，未学的标出来；⑩ **学会它之后能接着学**（下游，可点）；底部主按钮「去课堂学这一点 →」直接跳到对应的课堂步骤。这是拓扑图唯一真正的“超链接”，没有它图就只是一张海报。面板打开时如果节点被面板挡住，自动平移一点把它带进可见区。
  - 三个方向缺一不可：**前置**回答“学之前要会什么”，**课堂里一起讲**回答“这一步还讲什么”，**下游**回答“学完能干什么”。只做前置的面板，用户看完仍然不知道该往哪走。
  - **模块用颜色区分，并在图上方给一排可点的模块筛选**：点某个模块只亮它的知识点、其余变灰（透明度别低于 0.3，否则整张图像空了），面板里列出该模块的全部短名。
  - 节点上用原生 `<title>` 兜底：鼠标停一下能看到完整标题。
  - 考试闭包从各小问用到的知识点（`exam_refs`）出发，沿 hard 前置往回推出来，不能直接等于全部知识点，也不能按重要度算。闭包外的知识点变灰。
  - 模块级小图可以用 Mermaid
- 来源截图（备考页基本都要有，别跳过；它是第七节“引用即呈现”在课件页上的做法。EPUB 和课件里的图直接取原图文件放进 `img/`，正文里的图号、表号、例号、题号、式号都做成链接，点开弹窗显示原图或原文）：
  - 只导出知识点引用到的课件页，不逐页查看，几乎不耗 token。命令行的 `pdftoppm` 不一定装了；没有时用 `python3 -m pip install pymupdf`，`page.get_pixmap(dpi=120).save(...)`，横版课件页 120 dpi 大约 25–35 KB，几十张也就 2 MB 左右。
  - 文件命名 `img/<source>-<page 三位>.png`（例如 `img/M6-022.png`），和 `src` 里的 `page` 一一对应，重新导出时能直接覆盖。
  - 前端：出处那一行做成按钮（`Module 6 讲义 p.22`），点了弹窗显示原页；不要只写“见课件第 22 页”。弹窗要有标题（哪份材料第几页）和关闭按钮，点遮罩也能关。
  - 一个知识点可以有多张（不同课件都讲过同一件事），按 `src` 顺序都列出来。
  - 为什么必须做：PPT 在浏览器里打不开“第 N 页”，只给页码等于让用户自己去翻。这是“信息读不全”最直接的解法。
- 网页里的数据直接嵌在 index.html 中，`data/course.json` 作为正本另外保存
- **文件与页面必须有可辨识的名字，不能只叫 index**：
  - `<title>` 写成「课程代码 + 主题 + 版本」，格式如 `<课程代码> <课程名> · <主题>（<月-日> 版）`。
  - 本地文件夹名同样带课程与版本（`_学习网页_<主题>_<日期>/`），一门课多个版本、多个 agent 并行时靠它区分。
  - 发布版的应用名（`appName`）同样带课程代码，格式如「<课程代码> <主题>」；app 列表里所有课都叫「学习网页」就再也分不清哪门是哪门。
  - 同一个 app 重复发布会保留原名和原链接，所以名字只在第一次创建时定，之后不用改。

## 四、新建（有材料时）

### 1. 读材料
- 用你能用的文件工具读取用户给的文件夹或上传的文件。每个文件都读完：扫描页和手写页要做 OCR，图要逐页看。
- lecture 转写和网课文字稿同样重要：口头讲的例子、强调的重点（“这个会考”“这里很多人错”）、课件上没有的解释，都要提取出来，并标注时间点。
- 先回给用户一份文件清单，并标出读不了的文件。

### 2. 范围与准确性
- **课程学习和备考**：范围以课件和 lecture 为准，不添加课外内容。必须补的背景知识标“补充”。记号跟课件保持一致。
- **自学理解**：范围以用户的学习目标为准，材料只是起点。材料讲得不清楚或有错时，可以补充权威解释，但要标出来。网课转写稿常有识别错误和口误，要按上下文更正，并对照可靠来源核实关键事实和公式。不确定的地方要写明。

### 3. 拆知识点（拓扑图节点）与组织课堂步骤
两件事分开做：拓扑图上的知识点要细；课堂里的一步可以把几个关系紧密的知识点放在一起讲通。
- **拓扑图节点 = 能单独用题检验的一件事**（一个定义、性质、方法、题型或陷阱）。前置不同的、考题会单独考的，都单独成节点。例如“Wald 置信区间”要拆成参数的 CI、$\eta$ 的 CI、经 $g^{-1}$ 变换三个节点，因为考题会分别考。把整个模块或一组不同前置的内容合成一个节点是拆粗了。
- **课堂一步 = 一小撮能一口气讲通的内容**：围绕一个小问题展开（为什么需要 → 怎么做 → 得到什么），可以包含 1–5 个关系紧密的节点。分开讲会断掉逻辑的放在同一步，例如一个定义和它马上导出的性质、一个方法和它的推导。地图里点开一个节点，要能看到“课堂里和哪些点一起讲”。
- 数量只用来自查，不是指标：几个模块的备考通常有几十到一百多个节点。判断标准是“每个节点能不能单独出题、前置是否一致”，不要为了凑数硬拆或硬合。
- 学习类的深度先按材料的讲法定：材料推导了就到 `explain`，材料做了例题就到 `apply`。自学类按用户的目标定。

### 4. 建拓扑
- 组成有向无环图。出现循环说明拆错了，要重新拆。
- 课程学习类：按周次排，周内按依赖排。自学类：完全按依赖排。
- 拓扑图画到**知识点**这一层（格式见下面的“确认稿最低要求”）。模块图只是总览：可以另外用 Mermaid 画一张模块小图（实线表示必须先学，虚线表示只用到一个概念；节点上写编号范围），但它**不能代替**知识点拓扑图。图下面用一段话总结整张图有几条主线。

### 5. 先确认拓扑图，再生成
- 给用户确认的核心是**知识点拓扑图**，不是模块路线。做法：先把全部知识点一条条拆出来、打散；从考题（或学习目标）需要的知识点出发，找它们的前置、前置的前置……形成拓扑图。前置关系要跨模块连线（例如 Module 8 的题用到 Module 7 的工具、先修课的概念），让网页的讲法比学校材料更顺。
- 知识点编号按“即时前置”顺序排：每个前置刚好排在第一次用到它之前，不把先修内容堆在开头。
- 可以先发布一个只含地图、考情和学习路径的第一版网页，让用户直接在可交互的图上确认；确认后再分批生成课堂和题库。
- **前置知识放在哪**：前置知识按它在材料里本来的位置出现，不另外拎出来集中成一个模块：
  - 前置就在本课材料（教材、课件）里：按材料里本该出现的位置排，后面用到它的地方链回去。
  - 前置不在材料里（书里默认你已经会的知识、上一门课的工具）：放在第一次用到它的那一课、那一步之前，作为一小步补讲，标“补充”。
  - 不管放在哪，拓扑图上都要能点到它，并且节点标题就是在讲这件事。**自查**：把考情的逐题表从头看一遍，每个小问需要的知识点都能在图上点到。
- **只在用户能判断时才请他确认拓扑图**：用户手里有课件、考试范围，或者已经有相关基础时，才发给他确认。用户是入门者时不要让他确认，因为他判断不了对错；AI 自己对照课件或权威来源核对一遍，再直接放进网页。
- 跳过确认（不管是因为用户是入门者，还是时间来不及）时，拓扑图照样生成，放在地图板块里。

#### 确认稿最低要求
- 知识点粒度按四.3：拓扑图节点是能单独用题检验的一件事。“Module 7：Binomial regression、link、MLE、Wald 区间”把整个模块当成一个节点，太粗。“一口气讲通”是课堂一步的组织方式，不是拓扑图节点的标准。
- 每条写明：编号、所属模块、一句话内容、前置编号（可以跨模块）、对应的考题小问（备考时）。
- 写明知识点总数；备考时还要写考试闭包里有多少个知识点。
- 以可点击的拓扑图网页呈现（只含地图的第一版网页）：点一个知识点，亮出它的全部前置和后续；备考时提供“按考题看”，并且考情板块要按“考情板块最低要求”写完整。一条从 1 排到 11 的模块直线、按模块缩进的大纲，都不算拓扑图。
- 模块图可以作为总览放在旁边，但不能代替知识点拓扑图。

知识点清单样例（格式参考）：

| 编号 | 模块 | 内容 | 前置 | 考题小问 |
|---|---|---|---|---|
| 3 | M0 线代 | 谱分解：\(A=\Gamma\Lambda\Gamma^\top\) 的含义，用它求 \(A^{-1}\)、\(A^{1/2}\)，判断正定 | 1, 2 | — |
| 6 | M1 协方差 | 样本均值与样本协方差矩阵 \(S\)：定义、矩阵写法、无偏性 | 5 | 模拟卷 Q1(a) |
| 15 | M4 PCA | 第一主成分的定义：最大化 \(\operatorname{Var}(a^\top X)\)，约束 \(\lVert a\rVert=1\) | 14 | 模拟卷 Q2(a) |
| 16 | M4 PCA | 用拉格朗日乘子推出 PC1 是 \(\Sigma\) 最大特征值对应的特征向量 | 15, 3 | 模拟卷 Q2(b) |
| 17 | M4 PCA | 方差解释比例与选几个主成分 | 16 | 模拟卷 Q2(c) |

16 号的前置 3 号在线代模块里，这就是跨模块连线。课堂里 15–16 号可以放在同一步，按“目标 → 约束 → 推导 → 结论”一口气讲完。

## 四之二、没有材料时：先规划路线

### 1. 问清目标
- 要学到什么程度，学来做什么（看懂论文、做项目、面试、兴趣）
- 相关的基础会不会
- 每周有多少时间

能从对话里推断的就不问。

### 2. 调研
- 有联网搜索时，找这个领域公认的资源：大学公开课（课程主页、讲义、视频）、经典教材、官方文档、综述。优先找原始、权威的来源，记下链接以及具体的章节或讲次。
- 对照 2–3 个权威来源的大纲，归纳这个领域主要分哪几块、哪些是基础、哪些是进阶、它们之间的先后关系。

### 3. 出学习路线，先给用户确认
- **领域全景**：这个领域分哪几块；为了用户的目标，必须学哪几块，哪些可以先不学。
- **前置检查**：需要哪些基础。用户不确定自己会不会时，给 3–5 道诊断小题，按结果调整起点。
- **主线资源**：推荐一门课或一本书作为主线，其余作为补充，并说明理由（权威性、难度是否合适、是否免费可得）。
- **分阶段路线**：每个阶段写明：
  - 学习目标（可以检验）
  - 核心概念
  - 推荐资源（具体到章节或讲次，附链接）
  - 预计时间
  - 阶段检验方式

  阶段之间要说明“上一阶段解决了什么、这一阶段要解决什么新问题”。
- 请用户确认的是目标、时间和主线资源。知识点拓扑图不需要用户确认：AI 对照权威来源核对后，直接放进网页。

### 4. 用户确认路线后，做网页
- 学习路线就是地图。调研到的资料记为 sources（type 为 web 或 textbook），每个知识点都标来源。
- 讲解由 AI 依据这些来源来写，关键事实和公式要核实，给出原始链接，方便用户深入阅读。
- 用户后来拿到教材、课程转写稿或讲义时，作为新材料走增量更新（第五节）：补来源、补深度，不推倒重来。

### 5. 循循善诱的讲法
- 每一步从一个问题、现象或需求开始。先让用户想一想，可以先选一个猜测，再揭晓答案和道理。
- 一步只迈一小步，用已经学会的东西引出新的东西。
- 难的地方先给最简单的特例，再推广。
- 每个阶段结束时回顾：现在你能做到什么，还有什么问题是现有知识解决不了的，下一阶段就来解决它。

## 四之三、轻量入门（总时长少于 3 小时）

### 1. 怎么判断
满足下面两条就按轻量入门处理：
- 用户问的是一个概念或小主题，例如“什么是 X”“X 入门”“想了解一下 X”
- 估计总学习时间少于 3 小时，大约不超过 15 个知识点、1–3 课

超过这个体量时，改按“自学理解”或“从零规划”做。

### 2. 流程
- **不提问**，除非连主题本身都不明确。
- **不发路线等确认**：自己定好知识点和顺序，直接生成网页。
- 不知道用户的基础时，以“聪明的外行”为起点。需要的前置知识不要求先去学，而是在第 0 步给一份“前置小抄”：每个前置用一句话解释清楚。
- 能联网时，用搜索核实关键事实和公式，并在来源里给出链接。

### 3. 网页精简
- 只保留三个板块：
  - **课堂**：1–3 课，每课 5–10 步
  - **练习**：每个知识点 1–2 题
  - **简版地图**：知识点小拓扑图，要画出前置知识（例如学 API 时的客户端、服务器、HTTP），再加一条主线
- 不做考情、仿真题、真题、复习队列和进度码。计时器照常有，默认收起（见第三节）。
- 仍然保留：
  - 先讲直觉再写定义、一个例子贯穿全程
  - 人话框（数理类）
  - 每课最后的逻辑主线
  - 每个知识点的掌握标准和自测，答错时给针对性的解释
- 最后一页写“下一步可以学什么”。如果用户想深入，可以升级为“自学”或“从零规划”，在同一个网页上扩展。所以 `course.json` 这时也要照常保存。

## 五、增量更新（每周或每两周）

1. 读取 `course.json` 和新材料。
2. 从新材料里拆出知识点，逐条和已有知识点对比，归到下面某一种情况：

| 情况 | 处理 |
|---|---|
| 全新内容，前置都已有 | 新增 |
| 已有知识点的延伸或深化 | 新建一个知识点，以旧知识点为 hard 前置；不要塞进旧知识点 |
| 和已有知识点是同一个东西 | 不新建。在旧知识点上补来源；深度提高了就更新 `depth` |
| 老师更正了以前的内容 | 修改旧知识点，写入 `changed`，网页上加“已更正”标记 |
| **后补前置**（新内容其实是某个旧知识点的基础） | 新增这个前置，给旧知识点补上前置边。已发布的课不重排，在新的一课里加一张“回看”卡片，链接到旧知识点，并说明现在可以怎样重新理解它 |
| 新旧材料矛盾（记号或说法不同） | 两种说法都记下，标“待确认”，交付时问用户以哪个为准 |
| 加边后出现循环 | 把拆得太粗的知识点拆开，旧 ID 标 `merged`，指向拆分后的新知识点 |
| 新主题 | 新建模块。新内容能放进已有模块时就扩展已有模块，不要随便改模块名 |

3. 校验：所有 `pre` 指向的 ID 都存在且是 active；图里没有循环；没有任何知识点早于它的 hard 前置（后补前置除外，但必须有回看卡片）。
4. 内容有改动的旧知识点标“有更新，建议复看”，保留用户原来的勾选。
5. 写入 `changelog`，在地图的“本次更新”面板里显示：新增几个、更正几个、后补了几个前置、有哪些待确认。
6. 重新生成网页，写回同一个网页文件夹，并**重新发布到同一个 app**（先按 `course.json` 的 `deploy.dir` 找到目录，`deploy.app_id` 指向原来那个应用），用户的链接不变。

## 六、备考

### 1. 以考试为锚点，反推知识点
1. 给材料分优先级：**目标**是样卷或有官方答案的往年卷，**参考**是其他往年卷和作业，**主线**仍然是课件，tutorial 和 lab 作补充。
2. **拆题**：每道题拆到小问，再拆成它考的技能，列出“做对这一问必须会的知识点”。
3. **反推闭包**：从这些知识点出发，沿着 hard 前置一路往回找，得到考试需要的全部知识点。闭包以外的知识点降为次要或不考。
4. **深度校准**：按题目的问法定深度。同一个知识点被多道题考到时，取最深的一级：
   - 判断、选择 → `recall`
   - 解释、比较、问为什么 → `explain`
   - 计算、写代码、画图、按步骤做 → `apply`
   - 新场景、综合、设计 → `transfer`
5. **缺口检查**：
   - 考试要用、课件没讲的内容 → 写常识性讲解，标“课件未讲”
   - 课件讲了、考试说明明确排除的内容 → 标不考
   - 往年考过、今年课件没讲的内容 → 单独列出
6. 把结果写进考情板块，内容按下面的“考情板块最低要求”。考情在确认稿阶段就要写完整，因为它是用户确认范围的依据之一。
7. **学习路径**：按用户的可用时间切段。课堂始终按课程模块组织（一个模块一课，前置也按来源分课），这样以后可以复用；学习路径只引用课堂里的步骤（“今天学哪几课的哪几步”），不按天切课。冲刺版另附一个保底版，并列出“可以先砍”的编号；扎实版按天排，每天包含新学的内容和到期的复习。
   - **每一段必须写全这六样，缺一样就是没写完**：① 段号 + 日期（`第 3 天 · 11/13 周五`）；② 当天时长（`知识点约 3.6 小时，加上做题检验约 1–1.5 小时`，两者分开写，别合成一个数）；③ 为什么今天学这些（一句话，接上一段留下的问题）；④ 要学的知识点编号（可点，点了跳到地图并亮出）；⑤ 学完用哪些小问检验（可点，跳到题）；⑥ 当天已掌握 `x/y`（随勾选实时变）。
   - 每段末尾一个主按钮「开始第 N 天 →」，直接跳到当天第一个课堂步骤；不要在段里再嵌一遍课堂内容。
   - 段是按“用户能坐下来学的时长”切的，不是按模块切的：一个模块可能要拆成两天，两天也可能合一个模块。日期按考试倒推，写死日期，同时在旁边标“第 N 天”，这样用户隔两天回来也知道今天该是第几天。

#### 考情板块最低要求
考情板块要包含下面每一项（材料里确实没有的项，写明“材料中没有”，不要省略）：
- **考试事实卡**：日期和倒计时、时长（含阅读时间）、总分和占总评比例、作答语言、允许带的材料、考试范围（写明出自哪份公告、哪天发的）。
- **逐题表**：核心是按题号一眼看清这道题最重要的东西。每个小问一行，至少有：分值；考点（这一问考什么，一句话）；直接考到的知识点（编号 + 短名，可以点击，点了跳到地图并亮出这一问的考试闭包，也能跳到讲它的课堂步骤）。其他列按这门课的需要加，例如用到的公式、问法、闭包大小和“看路径”、对应的仿真题。列不要多，整张表要能一屏看清；易错点放进题卡（`traps`）里。
- **模块分量**：按分值汇总每个模块（和每种问法）的分数和占比，从高到低排。首屏一眼能看到分最多的几个模块和题型。
- **老师说过的话**：英文原话 + 中文翻译 + 日期 + 出处（哪份公告、哪节课的第几分钟）。
- **不考清单和材料缺口**：考试明确排除的内容；课件没讲但考试要用的内容（标“课件未讲”）；往年考过但今年没讲的内容。
- **往年题规律**：有多份卷子时，写每个题号位置通常考什么、哪些题型每年都出；只有一份样卷时写明“只有一份样卷，规律待验证”。
- **答题策略**：按分值分配作答时间、建议的做题顺序；用英文作答时，给常用的英文模板句型（例如检验题的结论怎么写）；允许带笔记时，写笔记纸该放哪些内容（公式、易混的判断、读输出的步骤）。

逐题表样例（格式参考）：

| 小问 | 分值 | 考点 | 用到的公式 | 知识点 | 闭包 |
|---|---|---|---|---|---|
| Q5(c) | 7 | 用偏差差反推 AIC | \(\mathrm{AIC}=D+2p\)（同一 \(\phi\) 下） | [31 偏差] [33 AIC 定义] [34 由偏差差反推] | 4 · 看路径 |

### 2. 冲刺版和扎实版

| | 冲刺版 | 扎实版 |
|---|---|---|
| 范围 | 闭包内全部知识点，只省掉从考试看极不重要的边角内容 | 闭包内全部知识点 |
| 讲解 | 和扎实版一样讲清楚：范围内的推导、中等重要和必要的内容、为后面打基础的次要前置，都不能省 | 按校准深度讲透；transfer 级要讲变式 |
| 变式与反复练 | 每个点练到会做即可 | 同一个点换着法子反复考，直到滚瓜烂熟 |
| 练习 | 直接用真题检验 | 先刷仿真题，熟练后再做真题 |
| 真题 | 边学边用 | 封存：某种题型的仿真题都达标后，才解锁对应的真题；最后整卷计时模拟 |

冲刺版比扎实版少的只有两样：从考试看极不重要的边角内容；同一个点“这样考完再那样考”的反复变式。讲解深度不打折扣：用户没学过的内容照样掰开揉碎讲清楚。时间实在不够时，先砍变式题，再砍边角内容的讲解；拓扑图、考情和主线内容的推导不砍。课堂按前置到后置的顺序生成和更新，用户按顺序学。

### 3. 仿真题（扎实版必须做）
- 每种考试题型写 3–6 道仿真题：考同样的技能，换场景、换数据，难度不低于真题。每道标出对应的真题类型（例如“样卷 2 Q2D 类”）和考的技能。
- 出题顺序：先出单一技能的题，再出组合技能的题，最后出和真题同等综合度的题。
- 每讲完一个模块，紧跟着就是这个模块的仿真题。
- 仿真题放在练习页，带“仿真”标签，不单开板块。

### 4. 真题手册
- 模块按考试分量排序；模块 0 是考试情报与答题策略；每个模块开头有一个“必背”框。
- 每道题包含：层级标签（官方答案 / 推导答案，推导答案注明非官方，并且结论已用代码或数值代入验证过）、出处和分值、原题、中文翻译（考试用英文时）、思路、默认折叠的答案、“已掌握”勾选。每个小问用全站统一的题卡。
- 考试用英文作答时，答案先给一段可以直接照着写的英文，再用中文解释为什么这样答。
- 一个整卷计时器（预设考试时长，可暂停、清零）和一个“展开 / 收起全部答案”开关。**不做每题计时**（用户不需要知道某道题卡了多久）；不做文字高亮、失分原因归类这类不常用的功能。
- **时间要拆成三段，不要只给一个总时长**：① 阅读时间单独一个计时器（考试规则允许先读不能动笔时，例如 15 分钟，跑完再开写作计时）；② 写作时长按分值折算成每题的“建议用时”写在题头上（`写作分钟 ÷ 总分 × 该题分值`，例如 180÷100×2 = 3.6 分钟）——这是静态提示，不是计时器，让用户知道这题大概该花多久；③ 整卷剩余时间常驻。写作计时 + 阅读计时 = 整卷用时。

### 5. Cheat Sheet 暂存（考试允许带笔记时都加上）

**它的定位是“临时收纳箱”，不是知识库。** 复习时看到觉得重要的一句话、一段公式、一张课件截图，随手丢进来，以后再翻。**不要给它加智能功能**：不自动打标签、不排序、不总结、不接 AI。用户可能从别处返回来看一眼再截图，再切到另一个地方粘贴，任何“自动记录上下文”的标签都会是错的，而纠正标签的成本比不打标签更高。

- 一个入口就够：页面顶部单行输入框，回车即存；在 Cheat Sheet 页任意位置 Ctrl/⌘+V 也能存。文字里的 LaTeX 自动渲染。
- **图片要能粘**（这是最常用的用法）：
  - 粘贴 / 拖拽 / 选文件三种都接：`paste` 监听 `clipboardData.items` 取 `image/*`，`drop` 取 `dataTransfer.files`，再加一个「选图」按钮兜底。
  - **存储用 IndexedDB，不用 localStorage**：localStorage 只有约 5 MB，一张手机截图转 base64 就 1–2 MB，粘三张就写不进去，而且 `setItem` 抛 `QuotaExceededError` 是静默的，用户会以为存了。用 `indexedDB` 一个 object store（`items`，keyPath `id`），**文字和图片都放这里**（不要一半 localStorage 一半 IDB，两边同步会出 bug）：图片存 **Blob**（比 base64 省 33%），文字存字符串。渲染图片时 `URL.createObjectURL(blob)`，缓存 URL，页面卸载时统一 `revokeObjectURL`。
  - 存前压缩：`createImageBitmap` → 长边缩到 ≤1600 px → `canvas.toBlob('image/webp', 0.85)`，课件截图缩完通常 80–200 KB，存几十张没问题。
  - 界面：卡片网格（`grid-template-columns:repeat(auto-fill,minmax(290px,1fr))`，不要用 `columns` 瀑布流，那会让卡片高低错落），按存入时间倒序（最新的在最前）。点缩略图全屏放大，左右键翻页，Esc 关。每条下面一行小字只写**存入时间**（`11/14 14:20`），不写“来自哪一课”——那个信息不可靠。
  - 可选：一条自由备注（用户想写就写，不填就空着）。
- 删除：卡片右上角一个 ×，点了就删（图片和文字都删），用底部提示条“已移除 · 撤销”，约 8 秒内可恢复；另在页底留“最近移除”区，过了提示条时间也能找回。
- **跨设备：做「导出备份 / 导入备份」，不做云同步（除非用户明确要求）**
  - 浏览器存储按「设备 + 浏览器 + 域名」隔离，手机粘的电脑看不到，这是浏览器的限制，不是 bug。**要在界面上说清楚**，否则用户会以为是坏了。
  - 导出：把全部条目（含图片，转 base64）打成一个 `{v,course,exported_at,items}` 的 json 下载，文件名带日期。
  - 导入：读 json，按 `id` 去重后合并（已存在就跳过），损坏的条目跳过并在提示里报数。
  - 代价是「手动搬一次」；换来的是不用开云服务、断网也能用、数据只在自己机器上。**云同步是另一档**：要开云服务、有配额、每次读写走网络，只在用户明确要求时做。
- 不做：多选批量操作之外的智能功能——不导出给 AI、不 AI 整理、不按知识点分组、不自动打标签。这些都会让它从一个“随手丢”的地方变成需要维护的东西。
- 允许用户自己把某几条**置顶**（一个图钉图标），因为他复习到最后会想先看那几条；置顶之外不排序。
- 工具条上要显示**条数和占用体积**（`4 条 · 本机保存 · 约 11 KB`），让用户知道离上限还有多远。

## 七、讲解写法

### 所有类型通用
- 每一课以第 0 步开头：这节课解决什么问题；学完你应该能……（可以检验的编号列表）。
- **引用即呈现（硬性要求）**：讲解、题目、提示和答案里引用的任何材料内容，都要把被引用的东西本身放进网页，不能只写出处让用户回原材料去找。用户只看网页，就应当等于读过了材料。具体包括：
  - 图表（“见图1-1”“表5-1”“Figure 3”）：在对应步骤显示原图（从 PDF、EPUB 或课件导出，或者按数据重绘），附图号和图题，可以点开放大
  - 例子与案例（“书中 IBM 的例子”“老师课上举的例子”“如例 3.2 所示”）：写出例子的条件、数据、过程和结论
  - 例题、作业题、往年题、样卷题（“仿照例 4.1”“同样卷 Q2”“根据上一问的结果”）：写出题面（考试用英文时附原文）和用到的数据；用到前一问的结果时，把那个结果也列出来
  - 公式、定理、定义、引文（“由式 (3.5)”“根据定理 2”“老师强调的那句话”）：写出完整内容和编号
  - 网页里其他步骤或其他课的内容（“第 5 章说过”“回看第 3 步”）：做成链接，点一下直接跳到那一步
  - 同一节里有、但讲解没点名的图表，折叠放在该步骤末尾
- 一个例子贯穿整课，后面的步骤反复用它。“先直觉、再定义、再例子”是常用顺序，不是固定顺序，每一步怎么组织见下面的“一步怎么讲”。
- 句子要短，说人话，不写空话。中文讲解，保留英文原词；考试用英文时，每一步都标出英文关键词。
- 课堂一次只显示一步；底部有上一步 / 下一步。卡片顶部写明：第 N 步 · 预计分钟数 · 知识点编号 · 英文术语。
- 左侧栏分三层，层级要一眼分清、不拥挤：
  - 单元（前置、Module X……）：可折叠的标题条，带底色和进度，只默认展开当前单元；只记录用户亲手点的展开 / 收起（不要把 <details> 初始化触发的 toggle 当成用户操作）
  - 课：每课一行，左边模块色点，右边进度小标签；当前课描边高亮；未生成的课变灰
  - 步骤：只在当前课下展开，用一条竖向时间线串起来，每步前是带编号的小圆点（完成变 ✓），字号更小，用时靠右；“本课主线”按钮放在步骤列表上方
- 卡片里按需要使用这些内容块：
  - 核心公式或定义框
  - 人话框
  - 例题框
  - 考点框：标注出处，按“下一步”逐行展开
  - 常见卡点框
  - 答题写法框
  - 了解即可（小字）
  - 回看卡片（增量更新时）
  - 自测
- 备考也要把学科讲通：样卷只代表题型和典型题，不代表闭包外的东西不会考。学会是目的，考试只是检测。
  - 每一步的“为什么现在学这个”写**学科上的动机**（上一步留下什么问题、这一步怎么解决），不写“因为要考”；考题出处单独列在每步末尾
  - 闭包外的知识点照样放进课堂、照样讲清楚，只是标为次要

### 一步怎么讲：讲透优先，结构跟着内容走
评价一步讲得好不好，只有一个标准：**这一步的内容有没有掰开揉碎讲透**。也就是说，一个没学过的人只读这一步（加上已学过的前置），能不能真正明白，并做对自测题。上面的内容块和下面的材料都只是工具箱，不是模板。
- 动笔前先想清楚两件事（不写进网页）：这一步**真正难懂的地方**是哪一两处；学的人最可能在哪里卡住或误解。篇幅主要花在这里：多给一层推理、一个算账的例子、一个反例，或者换个角度再讲一遍。
- 简单的东西一两句话说完，不为它单独开框，也不换着说法重复讲。
- 结构跟着这一步的推理走：可以从一个反常现象或问题讲起，再拆原因；可以先算账再总结；可以用一张对比表把几个案例串起来。不要求每一步都有定义框、例子框、卡点框、另一种看法框。
- 同一课里各步的结构应当不一样。连续几步都是同一串内容块，说明在套模板，要重写。
- 必须有的只有三样：学科上的动机（可以融进开头一段，不必单独一行“为什么现在学”）、自测题、出处。书外补充（更正、另一种看法、新数据）照样标“补充”，但只在它会改变理解时才写，并且写在相关的那段旁边，不固定放在末尾。
- 网页渲染要支持自由正文：一步可以是一段按需排版的正文，内容块的标签只在帮助阅读时才加。

下面是常用材料，按需取用，顺序跟着内容的推理走：
1. **为什么现在学**：一句话，写学科上的动机（上一步留下什么问题、这一步怎么解决）
2. **直觉**：1–3 句话，或者用贯穿例子里的具体数字引出问题
3. **定义 / 核心公式框**：公式单独成行居中
4. **人话**：紧贴公式下方，先逐个符号说明（是什么、形状是数 / 向量 / 矩阵、随机还是固定），再一句“某个量变大时结果怎么变”
5. **例题框**：用贯穿例子代入数字算一遍，每步一行
6. **常见卡点框**（有才写）
7. **自测题**：1–2 道，正好检验这一步的掌握标准
8. **考题出处**：最后一行小字，列出考到这一步的真题小问

### 公式与排版的固定写法（参照 MAST90138 复习课堂）
- **行内还是成行**：短符号写在行内（`$\hat\beta_1$`）；定义、核心公式、要背的结论单独成行居中。
- **推导链**：用 `aligned`，等号对齐，每行右边用 `\quad\text{（依据）}` 写一个短依据；很长的不等式或公式也用 `aligned` 分行，不要撑破卡片。
- **数值计算固定三段**：先写公式 → 再代入数字 → 再写结果，结果保留 3–4 位有效数字；所有数值用代码验算过。
- 公式里只用 `\text{}` 写短词，不写中文长句。
- **记号用真正的 LaTeX**，跟课件一致：向量、矩阵用粗体（\mathbf{X}、\boldsymbol\beta）；该花体的花体（Fisher 信息 \mathcal I、模型 \mathcal M、正态 \mathcal N）；运算符和分布名用正体（\operatorname{Var}、\mathrm{SS}_{\text{res}}、\mathrm{Bin}）。不要用 Unicode 拼凑公式（XᵀX、β̂、F(2,4) 这类）；知识点标题、掌握标准、选项、提示、真题翻译里也一样。只有 SVG 拓扑图节点标签用纯文本。
- 在 MathJax 配置里定义一套宏（如 \X、\bb、\SSres、\FI），全站共用，保证记号一致；用到 \boldsymbol 时要加载 boldsymbol 包。Python 里写含 LaTeX 的字符串一律用 r"…"。
- **反斜杠不要多转义**：r 字符串里再写 `\\`，或者把已经转义过的字符串再 json.dumps 一次，都会让公式里出现两个反斜杠紧跟字母（如 `\\texttt`、`\\beta`），MathJax 会把它显示成换行加一串斜体字母。生成网页后扫描全部数据字符串：公式里两个反斜杠只能用于 aligned 等环境里的换行，后面不能紧跟字母。
- **公式里不能直接写 `<`、`>`**：数据通过 innerHTML 插进页面时，`$\rk(\X)<p$` 里的 `<p` 会被浏览器当成 HTML 标签开头，后面整段被吞掉，露出 `$\rk(\X)` 这样的半截代码。生成网页时统一处理：遍历全部数据字符串（列表和元组都要遍历到，不要漏掉知识点标题、错误答案解释这类字段），在 `$..$`、`$$..$$`、`\(..\)`、`\[..\]` 内把 `<` 换成 `\lt `、`>` 换成 `\gt `；生成后再扫一遍，确认公式里没有剩下的 `<` `>`。匹配公式时，先把整段文字按 `$$..$$` 切开，只在切出来的公式以外的部分里找行内 `$..$`。如果直接对全文跑行内匹配，两个公式挨在一起时（比如 `$$F=P(1+r)^n$$</div><div>$P$ 是本金`），一个公式的结尾 `$` 会和下一个公式的开头 `$` 配成一对，中间的 HTML 标签被当成公式改写，页面上就会露出 `\lt /div\gt` 这样的乱码。发布前用浏览器逐页打开全部课堂步骤，检查页面上显示出来的文字里有没有残留的 `$`、`\`、`<`。
- **并列的内容竖排**（假设、步骤、对照表），带项目符号或编号，不要用分号横着串在一行里。
- **序号、出处标注、小标签不跟正文同字体同字号**：(I)–(V) 这类序号用小号衬线字、强调色；“M6 p.33”这类出处缩小、变灰、用等宽字；关键公式单独成行居中，太长的公式链用 aligned 分行。
- **序号全站统一样式**：不能只在课堂正文里套序号样式，选项、题面、知识点标题、提示、真题里的 (I)–(VI) 都要一样。做法：生成网页时在公式以外的文字里自动把 (I)…(VI) 包成序号样式的 span（class 不加引号，放进属性里也不会断）；页面里对数据先做 HTML 转义再显示的地方，转义函数要把这个 span 还原回来，否则会露出标签原文。
- **表格里的小标签不换行**：重要度、模块、状态这类标签列设 white-space:nowrap，标签用 inline-block，否则列被挤窄时“核心”会折成上下两行、看起来很扁。
- **内容块样式**：核心公式 / 定义框用浅蓝底 + 左侧蓝色粗线；例题框用浅暖色底 + 左侧暖色线；考点框用暖色描边圆角框；常见卡点用浅红底 + 左侧红线。
- **人话解释不加“人话”标签**：直接紧贴在它解释的公式或定义下方，用小一号（约 12.5px）的灰色正文字，左边一条蓝色虚线，和课件正文区分开。不要用楷体。
- 字体：标题用思源宋体（Noto Serif SC）；代码和数字用 JetBrains Mono；正文用苹方系，15.5px、1.75 倍行距。
- 类名不要和已有样式撞名（例如进度条的 .bar、地图的 .hint），发布前截图确认顶栏、侧栏和公式都正常显示。

### 逻辑主线（每一课和整门课都要有）
每一步都细讲之后，用户容易只见树木不见森林：学到后面，就忘了当初为什么要引出下一个概念、进入下一个步骤。所以每一课都要有一条主线：不讲细节，但因果关系清楚，把整课串起来。

**每课的最后一步是“逻辑主线”**
- 写成一条因果链，每一环一两句话：
  1. **问题**：之前的方法遇到了什么情况，为什么这个情况会让分析不准确或出错
  2. **思路**：解决它的核心想法，一句话
  3. **做法**：按顺序写出关键步骤。每一步只写“用什么（公式的名字或最简形式）求出什么”，以及求出来的值带回到哪里
  4. **结果**：最后解决了什么
  5. **新问题**：这个方法又带来了什么新问题或局限，由此引出下一环
- 一课里通常有好几轮“问题 → 解决 → 新问题”，依次串起来。
- 不重复细节：每一环都链接到讲这个细节的那一步。
- 示例（从树到随机森林）：
  - 单棵深树的方差大，换一份数据，树就变样
  - 思路：多长几棵树再取平均，降低方差
  - Bagging：用 bootstrap 抽 B 份样本，每份长一棵深树；回归取平均，分类用投票
  - 结果：方差降下来了。但树和树之间高度相关，平均后的方差 ρσ² + (1−ρ)σ²/B 最低只能降到 ρσ²
  - 随机森林：每次分裂只在随机选出的 m 个变量里挑，让树之间不那么相关
  - 新问题：没有单独的测试集，怎么估计误差 → OOB：用每棵树没抽到的样本来测
  - 新问题：几百棵树没法逐棵解读 → 变量重要性
- 配一道主线自测：把打乱的环节排回正确顺序，或者填空“为什么要从 X 走到 Y”。

**整门课的主线**：地图里放一段模块之间的主线，和拓扑图放在一起。每条模块之间的边配一句话：前一个模块留下了什么问题，后一个模块怎么接上。

**每一步都标出在主线上的位置**：卡片顶部显示一行主线位置（例如“问题 → 思路 → 【做法 2/4】 → 结果”），“为什么现在学这个”写在正文开头，可以融进第一段。

**复习线**：每一课开头先放主线，再进入压缩回顾。

**不同学科的写法**：
- 数理类：问题 → 方法 → 公式链 → 结果 → 新问题
- 论述类：论证脉络或因果脉络
- 编程类：需求 → 做法 → 局限 → 改进

备考时，主线还可以直接用作论述题的答题骨架。

### 按学科调整（需要才加，不需要不加）
- **数学、统计、计量、物理**：
  - 每个核心公式下面紧跟一个人话框，逐项说明每个符号是什么、形状（一个数 / 向量 / 矩阵）、随机还是固定、变大时结果怎么变
  - 代入具体数字验算一遍
  - 证明做成“下一步”逐行展开，每行写依据
  - 手算题配上快速检查方法
  - 能用交互演示（滑块、画布）讲清楚的地方就做
  - 全局配符号翻译器：符号 | 形状 | 随机/固定 | 大白话 | 在贯穿例子里的值
  - **讲到理解，不要只给公式**：步骤不能只有“公式 + 一个例子 + 一道题”。对核心公式或结论，在能帮助理解、也做得到的地方给出下面几项，不必每次齐全，按需要选：①它要解决的问题；②逐行推导，每行写依据；③几何或直觉上的解释；④条件不成立时会怎样；⑤用贯穿例子的数字验算。
  - 每个符号第一次出现时写明是什么、什么形状、随机还是固定；公式里用大括号（\underbrace）把各部分括出来，在下面写人话。例题、数据、R 输出写全，不只给题号。
- **编程、数据库**：
  - 在网页里做可运行的练习台：内置示例数据，按结果比对判分；报错翻译成中文，并说明常见原因
  - 代码逐行注释
  - 图用函数画（ER 图、关系模式记号等）
- **论述类学科**（商科、法律、人文社科）：
  - 答题模板：一句定义 → 案例里的具体对象 → 具体分析、举例或画图 → 理由和影响
  - 对比表、案例分析、论证结构
  - 不硬造公式
- **自学类**：
  - 不需要考点框、答题框；计时器照常保留，默认收起（见第三节）
  - 多用类比和反例
  - 每个模块末尾有一页“用自己的话复述”的提示，配一份参考复述供对照
  - 从零规划的课程按“四之二”第 5 条的引导式写法来讲

### 视觉：`references/ui-kit.css` 是**参考实现**，不是模板

**先说清楚这条的效力：它是参考，不是硬性模板。** `references/ui-kit.css`（来源：一版用户认可的课程页）给的是「一套被用户认可的呈现形式」，用它起步可以省掉从零配色，但**不要每个网页都长得一模一样**。

用户的原话：*「所有东西全部按照这个格式或者构架的话，很瘆人，而且学习的东西多了，容易记不清楚它在哪个网页的哪个部分。但如果不同的课用不同的颜色或者主题，潜意识就会比较容易区分。」*

所以分成三类：**必须统一的 / 每门课可以不同的 / 完全自由的**。

**A. 必须统一（这是“读起来不费劲”的原因，跟配色无关）**
1. **字号只有五级**：20 / 16 / 15 / 13.5 / 12.5。层级靠**变灰**（`--muted`）而不是靠字号乱跳；不要出现 11px 的正文。
2. **正文限宽**：`max-width:78ch`，引导语 `72ch`。铺满宽屏一行四十个字，眼睛回行会丢行。
3. **数字一律等宽** + `tabular-nums`（分值、计时、编号），否则列对不齐。
4. **表格外面套 `.tblwrap`**，`th` 吸顶；手机上转成“每行一张小卡”（`td` 带 `data-label`）。
5. **焦点态可见**：`outline:2px solid var(--accent)`，不要 `outline:none`。
6. **响应式断点两个**：900px（双栏塌单栏）、700px（手机重排）。手机字号整体上浮一档。
7. **不要用楷体**（试过，用户评价“丑的要死”）。

**B. 每门课必须不同（这是“潜意识能区分”的来源）**
- 每个网页有**自己的主题色**，写进 `course.json` 的 `theme` 字段：
  ```json
  "theme": {"hue":"215", "name":"深蓝", "accent":"#1F4E8C", "mark":"#FFE16A"}
  ```
- 主题色是**色相级**的差异，不是换个按钮颜色：`--accent`、模块配色、进度条、选中态、图上的模块色条全部由它派生（同一色相取不同明度/饱和度）。
- 选色按课程代码固定下来，下次做同一门课**沿用**，不要重抽：
  | 例子 | 色相 | 感觉 |
  |---|---|---|
  | 已经做过的课 | 沿用它 `course.json` 里的 `theme` | 不要改 |
  | 线性代数 / 数学类 | 265 靛紫 | 冷、抽象 |
  | 编程 / 数据类 | 165 墨绿 | 稳、终端感 |
  | 语言 / 人文类 | 25 赭橙 | 暖、纸感 |
  | 生物 / 医学类 | 340 洋红 | 有生命感 |
- **同一门课的多个网页保持同一主题色**，用户靠颜色认课；不同课之间**不要撞色**。
- 课程内的模块配色在主题色内部派生（同色相 12 档明度），不要引入第二种色相。

**C. 完全自由（别被参考实现绑住）**
- **布局骨架**：不是每门课都需要“左 270px 导航 + 主区”或“地图 + 360px 右栏”。按这门课的信息形态选：线性课程用单栏长页就够；有前置网络的才需要图；有大量真题的才需要逐题表。
- **内容块形状**：`def` 蓝框 / `ex` 灰虚线 / `exam` 橙左条 / `trap` 红左条 / `write` 浅灰底只是参考配方。可以换形状，只要满足一条：**不同语义靠形状或位置区分，不靠堆底色**（底色一多页面就花）。
- **背景层数**：参考实现是两种背景（`--paper` 浅灰 + `--card` 白）。想加一层就用主题色的极浅调（`color-mix(in srgb, var(--accent) 4%, #fff)`），不要引入无关色相。
- **组件取舍**：参考实现里的瀑布流、撤销条、事实卡、计时胶囊，按需取用，不需要就不放。

**D. 公式的表述方式——这条要照抄，不要自己发明**

这是用户点名要保留的部分（*「尤其是如何表述公式的」*），也是全篇**唯一的绝对底线**。用户原话：*「最核心的要求就是呈现出来的网页不能是有乱码的公式，或者用文字的形式打出来的公式。公式就要有公式的样子，罗马字不能被吃掉。」*

**底线（任何一条不满足就算没做完，不要交付）**：
1. **公式必须是排版后的图形**，不是源码。屏幕上出现 `$`、`\mathbf`、`\frac`、`\operatorname`、`$$` 任何一个，就是失败。
2. **不能用文字拼公式**。`β̂`、`Xᵀ`、`σ²`、`e^-u`、`sqrt(x)` 这类 Unicode/ASCII 拼法一律不许；必须是 LaTeX 经 MathJax 排出来的。
3. **罗马字（正体）不能被吃掉**。`\operatorname{rank}`、`\mathrm{tr}`、`\log`、`\exp`、`\det`、`\operatorname{Var}` 这类必须显示为正体字母；如果渲染后位置空了、字宽为 0、或者整个函数名消失，算失败。
4. **希腊字母、上下标、帽子、波浪线都不能丢**：`\hat{\boldsymbol\beta}`、`\tilde{\mathbf X}`、`\bar\tau` 要能看出帽子和波浪线。
5. **验收要截图看，不能只看 DOM 有没有 `mjx-container`**：容器存在但内容空白同样是坏的。截图里逐块扫一遍公式区，有空白/红字/源码就返工。

**具体做法**：
- **行内公式用 `$...$`，独立公式用 `$$...$$`**，不用 `\(...\)` / `\[...\]`（两种混用会让 MathJax 的配置和转义变复杂）。
- **定义一套宏，全站复用**，让公式短、渲染稳、源码可读：
  ```js
  window.MathJax={tex:{macros:{
    X:'\\mathbf{X}', y:'\\mathbf{y}', bb:'\\boldsymbol{\\beta}', bh:'\\hat{\\boldsymbol\\beta}',
    C:'\\mathbf{C}', bg:'\\boldsymbol\\gamma', rk:'\\operatorname{rank}',
    R:'\\mathbb{R}', MVN:'\\mathcal{N}', df:'\\operatorname{df}'
  }}}
  ```
  宏名用 1–3 个字符的短写（`\X` 而不是 `\designMatrix`），和板书习惯一致。
- **正体函数名一律用 `\operatorname{}` 或内置的 `\log \exp \det`，不要用 `\text{}`**：`\text{}` 会继承正文字体，在 SVG 输出里容易缺字形（这正是“罗马字被吃掉”的常见成因）。
- **定义/定理块里的公式独立成行居中**（`$$...$$`），正文引用时用行内（`$\rk(\X)=3$`），不要在一句话中间塞一段行间公式。
- **符号第一次出现时给中文读法**：`$\rk(\X)$（X 的秩）`。第二次以后不再解释。
- **中文里嵌公式，公式两侧不留空格**（`满足 $\X\C$ 满秩`），因为 MathJax 自己带间距，手加空格会变宽。
- **不要用图片代替公式**（截图里的公式不能复制、不能缩放、手机上糊）。
- **长公式必须能横滚**：`.mjx-container[display="true"]{max-width:100%;overflow-x:auto}`，桌面也会溢出。
- **短名字段（`short` / `svg` / 图上节点文字）必须是纯文本**：不能有 `$…$`、不能有反斜杠命令、不能有组合字符。图上节点是 SVG `<text>`，MathJax 管不到它，写进去就是原样显示 `满秩 $\iff\X^\top\X$ 可逆`。**组合字符尤其危险**：`β̂`（β + U+0302）、`Xᵀ`（U+1D40）、`ᵢ`（U+1D62）、`ⱼ`（U+2C7C）这些字体覆盖率极低，在很多机器上直接显示为空白——这就是用户说的“罗马字被吃掉”。图上只用中文 + 少量 ASCII + `×²≥` 这类常见符号，希腊字母可用单个 `β η γ φ`，但**不要加帽子/下标/上标**。

**怎么验（必须做，不能靠“看起来差不多”）**

在页面里跑一次体检，四个数都必须是 0：

| 检查 | 含义 |
|---|---|
| 正文叶子节点里含成对 `$…$` 的个数 | 有漏排版 |
| SVG `<text>` 里含 `$` 或 `\` 的个数 | 图上露源码 |
| `mjx-container` 里没有 `<svg>` 的个数 | 排版失败留空壳 |
| 控制台错误数 | 排版链路本身坏了 |

```js
// 注入到 </body> 前，结果写到 <html data-test>，再用 --dump-dom 抓
setTimeout(()=>{
  const raw=[...document.querySelectorAll('body *')].filter(e=>!e.children.length
    && /\$[^$]{1,60}\$/.test(e.textContent||'') && !e.closest('script,style')).length;
  const svgBad=[...document.querySelectorAll('svg text')].filter(t=>/[\\$]/.test(t.textContent||'')).length;
  const empty=[...document.querySelectorAll('mjx-container')].filter(c=>!c.querySelector('svg')).length;
  document.documentElement.setAttribute('data-test',JSON.stringify({raw,svgBad,empty,mj:document.querySelectorAll('mjx-container').length}));
},6000);
```

**注意**：`mjx-container` 数量大于 0 不代表没问题——容器存在但里面没有 `<svg>` 同样是坏的。所以必须同时查 `empty`，并且**截图抽查**几块公式密集的区域（考情表、真题答案、详情面板）。每个视图都要过一遍（课堂 / 刷题 / 地图 / 路径 / 考情 / 真题 / Cheat Sheet），漏排往往只出现在某个动态插入的地方。

**根治办法是加一道兜底**：每次渲染后扫一遍 `body` 里含成对 `$…$` 的文本节点，把它们的父元素丢给 `MathJax.typesetPromise`（去抖 150 ms）。这样即使某处忘了调 `tex()`，源码也不会留在页面上。但要记住：兜底只对 HTML 有效，SVG 里的文字它救不了——所以短名字段必须一开始就是纯文本。

#### 响应式：手机必须单独调，不能靠浏览器自动缩放

用户的原话：*「换手机排版和电脑排版的时候可能会有点不舒服以及看得比较费劲」*。

- **手机字号整体上浮一档**：`body` 16px，说明文字 13.5px，编号 12.5px。12.5px 的正文在手机上要眯眼，这是“看得费劲”最主要的原因。
- **可点元素够大**：按钮 ≥38px 高、选项 ≥44px、chip ≥30px、图上的缩放按钮 40×40；上一步/下一步各占半行。
- **表格换形态**：手机上不是横向滚动，而是“每行一张小卡”，列名靠 `td` 的 `data-label` 显示。**写表格时就要带 `data-label`**，否则手机上会变成没有列名的数字堆。
- **顶栏收起来**：主板块标签独占一行横向滚动，课程代码隐藏，次要按钮加 `.hide-m` 隐掉。
- **验收**：必须用 iframe 套 390px 宽截图（直接 `--window-size=390` 会得到 485px 的页面被裁成 390px 的假溢出），确认无横向滚动、字号可读、表格已转卡片。细节见 `references/ui-kit.md` 第六节。

## 八、怎样确保真的掌握了

### 1. 每个知识点都写明掌握标准
写在 `mastery` 里，必须能用题检验。比如写“能对任意 2×2 协方差矩阵手算特征分解，并验算”，而不是“理解谱分解”。

### 2. 题目按深度分级
- `recall`：判断题、选择题。错误选项要对应真实的常见误解，不能凑数
- `explain`：选出正确的“为什么”；给一段错误解释，让用户找出错在哪
- `apply`：数值填空（有容差）；代码或 SQL 在网页里运行，按结果判分；排序题、步骤填空
- `transfer`：新场景综合题；开放题配评分要点清单，用户逐条自评后再看参考答案

### 3. 题目数据
```json
{"id":"q-…", "points":["…"], "type":"mcq|tf|numeric|order|code|open", "tags":["自测|仿真|真题"],
 "mimic":"样卷2 Q2D 类", "depth":"apply", "marks":2, "src":"样卷 Q1(a)",
 "en":"英文题面（考试用英文时）", "zh":"中文题面",
 "items":["tf 每题一个陈述，answer 是对应的布尔数组"],
 "answer":"…", "check":"判分方式", "hints":["第一级：思路方向", "第二级：关键一步"],
 "traps":[{"wrong":"常见错误答案", "why":"针对这个错误的解释，并指向相关知识点"}],
 "rubric":["开放题评分要点"], "official":true}
```
- **`marks` 必填**（备考）：掌握度按分值加权、每题建议用时都靠它算。没有分值的题按 1 分计，但真题一定要填真分值。
- **`tf` 是独立题型，不要用 `mcq` 顶**：考试里“勾出总是成立的选项 / tick the option(s) that are always TRUE”这一型，和四选一不是一回事——每个选项各自独立判对错、可多选、按选项给分（常见 2 分/选项），漏勾和多勾都扣分。数据上写 `"type":"tf"`，`items` 放每个选项的陈述，`answer` 放布尔数组（第几个该勾）。题卡渲染成每个选项一行 + 「对 / 错」两个按钮，作答后逐项显示对错和得分，不要合并成一个“选 A/B/C/D”。2026 那次两版都栽在这里：一版建了 `tf`（22 道），另一版拿 `mcq` 硬顶，20 分的大题格式就错了。
- **错误答案库**：每道题预设 1–3 个常见错误答案。用户的答案命中时，给出针对性解释（例如“你多列了 Sunshine，因为……”），不能只显示“错误”。
- **两级提示**：先给思路方向，再给关键一步。
- 考试规则禁用的写法（例如禁用 inline view）在判分时直接拦下，并说明原因。

### 4. 掌握状态与错题本（只用一个勾选框）
- 每道题只有两种状态：**未掌握 / 已掌握**，就是题卡右上角那个“已掌握”勾选框，**只由用户自己勾**。
- 作答只给即时反馈（对错和针对性解释），不自动改状态、不自动进错题本。用户可以随便点选项、反复作答，都不会被记成错题。
- **错题本 = 练习页的“未掌握”筛选**：做过、但还没勾“已掌握”的题。勾上就离开错题本；取消勾选就回来。不做“撤销”“已订正”等另外的按钮和状态，也不做间隔复习队列。
- 知识点的进度由它的题推出来：相关题都勾了“已掌握”，这个知识点就算掌握。
- **备考页的掌握度按分值加权，不按题数**：顶栏和真题手册显示 `已掌握 34/100 分`，不是 `已掌握 12/113 题`。理由很实际——2 分的小问和 22 分的大题对考试不等价，按题数算会把“做掉一堆 2 分判断题”误读成“已经拿下一半”。实现：`Σ(已掌握题的 marks) / Σ(全部 marks)`，分母只算真题/仿真题里属于考试范围的部分，并在小字里同时给出“共 N 题、已掌握 M 题”，两个数都在，别只留一个。
- 答错时，除了针对性解释，再提示“可能是前置 X 没掌握”，链接到前置知识点。
- 进度码可以把薄弱点告诉 AI。下次更新时，加强这些知识点的讲解，并补充针对性的题目。

## 八之二、自我改进：用户不满意时，不只改网页，还要判断要不要改 skill

用户在生成后提出不满意、要求修改或调试网页时，按下面的步骤处理。AI 自己在交付前检查时发现了规则没覆盖到的问题，也走同样的流程。

**在同一个对话里一直有效**：只要这个对话里调用过本 skill，用户之后提出的任何修改意见、不满、新偏好或新约束，都按本节处理，即使那条消息没有再带上本 skill 的名字或斜杠命令，也不管隔了多少轮、中间聊过别的什么。不要等用户再次点名 skill 才考虑写进 skill；也不要因为用户这次没提 skill，就只改网页、不做第 2 步的归因。上一轮提出的 skill 修改卡片用户还没保存时，新的建议要把上一轮的内容合并进来，并告诉用户只保存最新一张。

### 1. 先把当前网页改好
按用户的要求修改 course.json 和网页。

### 2. 归因：判断问题的适用范围

| 范围 | 典型例子 | 怎么处理 |
|---|---|---|
| **仅这门课** | 这门课老师的记号、某个知识点讲错了、用户对这门课有特别的偏好 | 只改网页，并写进 course.json 的 `course_notes`，以后更新这门课时一律遵守。不改 skill |
| **某一类学科或规格** | 公式晦涩、推导跳步（数理类）；代码题判分太死板（编程类）；仿真题太像原题（备考·扎实） | 提出 skill 迭代建议，把规则加在对应学科或规格的那一节 |
| **所有学科都会发生** | 知识点拆得太粗或太碎、逻辑主线太笼统、自测题太简单 | 提出 skill 迭代建议，把规则加在通用的那一节 |

判断时要回答两个问题：
- 问题出在 skill 的哪一条规则上？是规则缺失、写得含糊，还是规则本身没问题、只是这次没做到？只是没做到时，不改 skill。
- 拿一门别的学科（或另一种规格）套用现在的规则，会不会出同样的问题？要举一个具体的例子。

判断不了时，把两种可能和各自的理由说出来，让用户选。

### 3. 提出 skill 迭代建议（先问，不直接改）
在这一轮回复的最后写一段“skill 迭代建议”：问题是什么；判断的范围，以及为什么不是“仅这门课”；拟新增或修改的规则原文，写明放进哪一节；会不会影响其他学科或规格。然后让用户选：采纳 / 换一个范围采纳（例如只用于数理类）/ 不采纳。**没有得到确认，不改 skill。**

示例：用户说“公式晦涩难懂、知识点讲得不深”。判断：公式多的课都会碰到，论述类课程不会，所以范围是“数理类”。建议在“按学科调整 → 数学、统计、计量、物理”里加一条讲解细度约束（例如：推导中每一行只做一种变换并写出依据；新符号在同一步里解释；一个知识点里的新公式不超过一个），先问用户要不要加，确认后再写入。

### 4. 用户确认后，更新 skill
- 能写入 skill 所在的文件夹时（例如 `~/.agents/skills/painless-learning-web/`、`~/.workbuddy/skills/painless-learning-web/`，或用户的 GitHub 仓库），直接修改这个 SKILL.md 的对应章节。
- 写不进去时，给出可以直接粘贴的修改内容（位置 + 新文本），并提醒用户：其他 agent 里装的副本也要同步。
- 在 `references/rule-changelog.md` 末尾追加一条：日期、触发的问题、适用范围、改了哪里。
- 用新规则重新检查当前网页，确保已经符合。

### 5. 规则怎么写
- 要具体、能检验：写“每个公式下面必须……”“每个知识点不超过……”，不写“讲得更清楚一些”这样的空话。
- 放在最窄的合适范围里：能放进学科小节的，就不放进通用小节。
- 和已有规则重叠或冲突时，改写或合并旧规则，不在后面叠加一条新的。
- 能被检查的规则，同时加进“交付前检查”。

## 十、交付
- **交付的第一步是发布，不是给本地路径**：网页生成或更新完、校验通过、自己打开看过之后，直接发布成链接，回复里放分享链接。默认不问“要不要发布”，也不要把“本地文件已生成”当成交付完成。
- **发布后把位置记下来**：`data/course.json` 里写 `deploy`（目录 / app_name / share_link / app_id / published_at）。下次要改，先读这个字段找到目录；找不到就先找（目录名、`.wbapp_*.genie`），**不要新建一份**。
- 新建或切换到备考时：用户能判断拓扑图对不对时（有课件、考试范围或相关基础），先发知识点拓扑图（可以是只含地图的第一版网页）给用户确认，再生成完整网页；用户是入门者或时间来不及确认时直接生成，但拓扑图照样要有。从零规划时，先发学习路线给用户确认。轻量入门不需要确认，直接生成网页，并用一句话说明预计学习时长。这类“先确认拓扑图 / 先确认路线”的中间稿也照样发布，让用户点开就能看图。
- 增量更新时：改的是同一个发布版（先按 `deploy.dir` 找到目录），重新发布到同一个 app，链接保持不变；然后一句话说明新增和更正了几个知识点，并列出待确认的矛盾。
- 每次附一句话：说明这次用的是哪种类型；可以把进度码发过来，下次会针对薄弱点加强。
- 用户提出修改意见后（不论这条消息有没有再带上本 skill，只要这个对话里调用过本 skill）：先改网页，再按“八之二、自我改进”判断问题范围，需要时在回复最后提出 skill 迭代建议，确认后才改 skill。
